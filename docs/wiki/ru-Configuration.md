# Настройка

Network Control настраивается в самой панели: при первом запуске в **мастере первичной настройки**, дальше на странице
**Настройки**. Настройки хранятся в PostgreSQL, и все процессы подхватывают их в течение 15 секунд, перезапуск не нужен.

## `.env`

Здесь только то, что нужно встроенным контейнерам до запуска панели. `install.sh` создаёт файл со случайными паролями.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `POSTGRES_PASSWORD` | — | Пароль встроенного PostgreSQL (TimescaleDB). Вводится один раз в мастере, дальше панель хранит его в OpenBao |
| `CLICKHOUSE_PASSWORD` | — | Пароль встроенного ClickHouse. Вводится один раз в мастере, хранится в OpenBao |
| `NC_VERSION` | `2.0.0` | Версия образов |
| `PANEL_PORT` | `8080` | Порт панели |
| `FLOW_PORT` / `SFLOW_PORT` | `2055` / `6343` | UDP-порты коллектора потоков |
| `OPENBAO_VERSION` / `CLICKHOUSE_VERSION` | `2.6.2` / `24.8` | Версии образов встроенных сервисов |

Больше backend ничего из окружения не читает. Значения из старого `.env` (`AWG_HOST`, `ROUTER_HOST`, `DATABASE_URL`,
`SPA_CONNECTION_KEY` и т. д.) импортируются **один раз**, если в базе их ещё нет; предупреждение в журнале напомнит
убрать их из `.env`.

## Мастер первичной настройки

Открывается сам, пока Network Control не настроен. На каждом шаге нужен **код установки**: его печатает `install.sh`,
он есть в `docker compose logs backend` и в файле `data/backend/setup-code`. После мастера код исчезает.

1. **Хранилища**: PostgreSQL (TimescaleDB), ClickHouse и OpenBao. Значения встроенных сервисов уже заполнены. OpenBao
   из compose мастер инициализирует сам: **root-токен и ключ восстановления показываются один раз**, сохраните их в
   менеджере паролей. Внешний OpenBao подключается через AppRole (`role_id`, `secret_id`, хранилище KV v2).
   Результат: `data/backend/bootstrap.json` (адреса и имена пользователей, без паролей) и `data/backend/approle/`
   (единственный секрет на диске). Пароли уходят в OpenBao (`infra/postgres`, `infra/clickhouse`).
2. **Вход**: адрес панели и способ входа:
   - **Пользователи Network Control**: самостоятельная установка. Здесь создаётся первый администратор; пароли (argon2id)
     и секреты TOTP хранятся в OpenBao (`local/users/<id>`) и никогда не попадают в PostgreSQL;
   - **Keystone**: ключ подключения `spa1.…` (см. ниже); у кого-то должна быть роль `admin` этого приложения.

Дальше чек-лист **«Первые шаги»** на обзоре проводит по остальному: роутер, сервер Amnezia, шлюз, первое устройство,
потоки, VPN-клиент, Telegram и резервные копии.

### Шлюз

**«Создать клиента шлюза»** создаёт клиента AmneziaWG `home-gateway` и записывает его конфигурацию в
`awg-client/config/awg0.conf`. awg-client ждёт этот файл и перезапускает туннель при каждом изменении его или
`gateway.json`.

## Вход: локальные пользователи и Keystone

В локальном режиме на странице **«Пользователи»** можно создавать пользователей, менять роль, отключать, сбрасывать
пароль, отключать TOTP и удалять. Каждый меняет временный пароль при первом входе и может включить TOTP в профиле.

### Подключение Keystone (SPA)

1. В Keystone: **«Приложения → Подключить приложение»**, тип `network-control`, адрес панели. Адрес возврата:
   `<адрес>/api/auth/spa/callback`, адрес после выхода: `<адрес>/`.
2. Назначьте людям или группам роли `admin`, `operator`, `viewer`, себе в первую очередь `admin`.
3. Вставьте ключ подключения в **«Настройки → SPA»** (он сохраняется в OpenBao `spa/connection_key`).

### Перенос локальных пользователей в Keystone

В локальном режиме, когда ключ уже сохранён:

1. В Keystone откройте приложение и **разрешите перенос пользователей**. Окно закрывается после одного переноса или
   через 24 часа.
2. **«Перенести локальных пользователей»**: пользователи уходят вместе с argon2id-хешами паролей и ролями
   (`POST /api/spa/v1/users/import`). Keystone сохраняет пароли (перехеширует при первом входе) и сообщает о занятых
   логинах и e-mail. TOTP в Keystone настраивается заново.
3. **«Перейти на Keystone»**: не сработает, пока ни у кого в Keystone нет роли `admin` этого приложения. Синхронизация
   привяжет локальные записи по логину и отключит остальные; при желании локальные пароли и секреты TOTP удаляются из
   OpenBao.

**«Вернуться к локальным пользователям»** возвращает вход в панель (войти смогут только люди с локальным паролем).
Если войти не может никто: `docker compose exec backend python -m app.cli create-admin <логин>`.
