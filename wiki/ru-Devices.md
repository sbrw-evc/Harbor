# Сетевые устройства

[English](Devices.md) · **Русский**

Harbor управляет маршрутизаторами, коммутаторами, межсетевыми экранами, точками доступа, контроллерами и
серверами домашних и корпоративных производителей. Каждое устройство опрашивается по расписанию: панель хранит его
сведения, интерфейсы с текущей скоростью, соседей LLDP / CDP / MNDP, устройства за контроллером и видимых клиентов.
Эти же данные строят [карту сети](ru-Network-Map.md) и дают имена экспортёрам, интерфейсам и хостам LAN в
[анализе потоков](ru-Flows.md).

## Добавление устройства

**Устройства → Добавить**: платформа и подключение, адрес, учётные данные, при необходимости — расположение и адрес,
с которого устройство отправляет потоки. **Проверить подключение** собирает данные без сохранения и показывает, что
найдено. **Найти в сети** проверяет адрес или подсеть (до /22) — баннер SSH, веб-интерфейс и SNMP sysObjectID — и
предлагает платформу.

Когда задан адрес роутера («Настройки → Роутер»), маршрутизатор добавляется автоматически (MikroTik по SSH с ключом панели из
OpenBao `infra/ssh`, RouterOS 7.13+). Для RouterOS старше 7.13 переключите его на REST API или SNMP.

### Учётные записи на устройствах

Заведите отдельную учётную запись с минимальными правами под нужные действия:

| Платформа | Только мониторинг | Мониторинг и изменения |
|---|---|---|
| MikroTik | группа с `read,api,rest-api` (REST) или `read,ssh` | добавить `write,reboot` |
| Cisco / Dell / Aruba / Eltex | privilege 1 и команды `show` (или пароль `enable` в форме) | privilege 15 |
| Juniper | класс `read-only` | класс `super-user` или свой класс |
| OPNsense | API-ключ пользователя со страницами *Diagnostics* | добавить *System: Firmware / Reboot*, *Diagnostics: NetFlow* |
| pfSense | ключ REST API с правами чтения | добавить нужные endpoint'ы |
| FortiGate | REST API admin с профилем read-only | профиль read-write |
| Omada | приложение Open API с ролью *Viewer* | роль *Admin* |
| UniFi | локальный пользователь *View Only* | *Site Admin* |
| SNMP | community / пользователь v3 только для чтения | community / пользователь v3 с правом записи |

## Опрос

Устройства опрашиваются каждые `poll_seconds` (по умолчанию 300 с, минимум 60 с) процессом-лидером, по шесть
одновременно. Скорость и загрузка интерфейсов считаются по приросту счётчиков между опросами. Два неудачных опроса
подряд переводят устройство в состояние «недоступно» и поднимают критический алерт `device.down.<id>` (в том числе в
Telegram); он снимается следующим успешным опросом. **Опросить** на странице устройства запускает опрос сразу.

## Настройка из панели

Вкладка **Управление** показывает только то, что поддерживают платформа и выбранное подключение:

- **Имя**, **DNS**, **NTP**, **интерфейсы** (включение, описание) — оператор и администратор.
- **Экспорт потоков** — настраивает NetFlow v5 / v9, IPFIX или sFlow на коллектор панели (по умолчанию адрес шлюза,
  порт 2055; sFlow — 6343). После этого устройство появляется в *Анализ потоков → Экспортёры*.
- **Перезагрузка**, **консоль CLI**, **резервная копия конфигурации** — только администратор.
- **Блокировка клиента** — на UniFi, Omada и Keenetic (вкладка «Клиенты» или страница «Клиенты сети»).

Каждое изменение пишется в журнал аудита с параметрами (команды CLI — до 300 символов). Значения, которые попадают в
команды устройства, строго проверяются: имена `[A-Za-z0-9._-]`, описания без кавычек и спецсимволов, серверы — IP или
имя хоста.

## Клиенты сети

Клиенты объединяются со всех устройств по MAC-адресу: ARP, аренды DHCP, ассоциации Wi-Fi, списки клиентов
контроллеров и таблицы MAC портов коммутаторов (порты с соседом LLDP / CDP — это uplink, они пропускаются). Точка
подключения — самый точный источник: Wi-Fi > контроллер > порт коммутатора > DHCP > ARP. Производитель — из реестра
IEEE OUI (скачивается раз в неделю в `data/backend/oui.tsv`); случайные MAC Wi-Fi помечаются.

Клиент онлайн, если его видели не позже `endpoint_offline_minutes` (15) минут назад; клиенты без имени, которых не
видели `endpoint_retention_days` (90) дней, забываются. Имя клиента показывается на карте и в анализе потоков
(измерение `LocalHost`).

## Безопасность

- Учётные данные хранятся только в OpenBao (`devices/<id>`); API отдаёт флаги `*_set`, но не сами секреты.
- Ключ SSH-сервера запоминается при первом подключении (trust on first use); при смене ключа опрос останавливается,
  пока администратор не сбросит ключ на странице устройства.
- HTTPS-сертификаты устройств по умолчанию не проверяются (самоподписанные); включите **Проверять TLS-сертификат**,
  если на устройстве доверенный сертификат.
