# VPN на OPNsense

[English](OPNsense-VPN.md) · **Русский**

Третий VPN-сервер панели рядом с Amnezia на VPS и WireGuard на MikroTik: инстанс WireGuard на межсетевом экране
OPNsense (24.1 и новее, плагин WireGuard входит в ядро). Панель управляет пирами одного инстанса через REST API
OPNsense; это обычные клиенты панели — создание, блокировка, квоты, сроки доступа, перевыпуск ключей, трафик, карта
подключений, QR-коды и одноразовые ссылки работают так же, как для остальных серверов.

| | Amnezia (VPS) | MikroTik (дом) | OPNsense |
|---|---|---|---|
| Протокол | AmneziaWG (обфускация) | WireGuard | WireGuard |
| Выход в интернет | VPS | Домашний провайдер; сайты из списка — через Amnezia | По маршрутизации OPNsense |
| Доступ в домашнюю сеть | — | Да | По правилам межсетевого экрана OPNsense |
| Кто настраивает сервер | Панель | Панель (**Настроить на MikroTik**) | Вы, в OPNsense |
| Как панель до него достаёт | SSH | SSH | HTTPS (API-ключ) |

## Что настраивается в OPNsense

Инстанс, NAT и правила межсетевого экрана панель не создаёт — их один раз настраивают в OPNsense:

1. **VPN → WireGuard → Instances**: инстанс (например `wg0`, порт `51821`, адрес туннеля `10.10.0.1/24`).
   **VPN → WireGuard → Settings**: WireGuard включён.
2. Firewall: правило на WAN, пропускающее порт (UDP `51821`); правила на интерфейсе WireGuard — куда клиентам можно;
   outbound NAT для `10.10.0.0/24`, если клиенты выходят в интернет через OPNsense.
3. Если OPNsense стоит за другим роутером (например MikroTik) — проброс UDP `51821` на OPNsense.
4. **System → Access → Users**: пользователь для панели с правами на страницы WireGuard (`VPN: WireGuard`) и его
   API-ключ (**API keys → +**, скачивается файл с `key` и `secret`).

## Подключение панели

1. **Настройки → WireGuard на OPNsense**: адрес OPNsense (`opn_host`, например `192.168.0.50`), инстанс
   (`opn_wg_instance`: имя или устройство, по умолчанию `wg0`) и проверка сертификата TLS (`opn_verify_tls`;
   выключите для самоподписанного сертификата, который у OPNsense после установки).
2. **VPN на OPNsense → API-ключ OPNsense**: ключ и секрет. Панель сначала проверяет их на API и хранит только в
   OpenBao (`opnsense/api`); в базе данных ничего секретного нет. **Убрать** удаляет ключ — панель перестаёт
   управлять пирами, сами пиры остаются на OPNsense.

На странице видно состояние инстанса: устройство, порт, сеть клиентов, адрес OPNsense в туннеле, публичный ключ,
число пиров (заблокированных, онлайн).

## Параметры конфигов клиентов

| Параметр | По умолчанию | Описание |
|---|---|---|
| Адрес подключения (`opn_endpoint_host`) | публичный IP MikroTik перед OPNsense (если роутер задан) | Домен или адрес; порт — порт инстанса |
| DNS (`opn_client_dns`) | адрес OPNsense в туннеле (`10.10.0.1`) | Unbound на OPNsense должен пускать сеть туннеля (Access Lists) |
| AllowedIPs (`opn_allowed_ips`) | `0.0.0.0/0` | Пресет «Только домашняя сеть»: `LAN_CIDR, <сеть инстанса>` |

Изменения применяются к конфигам, скачанным после сохранения.

## Как панель работает с API

| Действие | API |
|---|---|
| Инстанс | `GET /api/wireguard/server/searchServer`, `getServer/{uuid}` |
| Пиры | `POST /api/wireguard/client/searchClient` — пиры, у которых в `servers` есть инстанс |
| Новый клиент | `addClient` с `enabled`, `name`, `pubkey`, `psk`, `tunneladdress` (следующий свободный адрес сети инстанса), `servers` |
| Блокировка, переименование, перевыпуск ключей | `setClient/{uuid}` с `enabled` / `name` / `pubkey` — всегда вместе с `servers`, прочитанным через `getClient` (без него OPNsense отвязывает пира от инстанса) |
| Удаление | `delClient/{uuid}` |
| Применение | `POST /api/wireguard/service/reconfigure` после каждого изменения |
| Трафик | `GET /api/wireguard/service/show`: rx/tx, последнее рукопожатие, endpoint пиров устройства инстанса |

Пиры, созданные в OPNsense вручную, импортируются кнопкой **Синхронизировать** без закрытого ключа — перевыпустите
ключи, чтобы получить конфиг. Пиры других инстансов не трогаются.

## Диагностика

| Симптом | Причина |
|---|---|
| «API отказал в доступе (401/403)» | Неверный ключ или у пользователя нет прав на WireGuard |
| «API недоступен» | Адрес, порт HTTPS, интерфейсы веб-интерфейса или включённая проверка TLS при самоподписанном сертификате |
| «Инстанс WireGuard «wg0» не найден» | Значение `opn_wg_instance` не совпадает ни с именем, ни с устройством инстанса |
| Клиент подключается, рукопожатия нет | Проброс порта / правило на WAN или адрес подключения в конфиге |
| Рукопожатие есть, трафика нет | Правила интерфейса WireGuard, outbound NAT, access list DNS |
